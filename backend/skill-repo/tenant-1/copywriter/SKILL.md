# 文案工坊 / CopySmith

## Overview

通用文案创作与改写技能包，把"写文案"拆成两条清晰路径：

- **Mode A · 关键词创作**：用户只给关键词/主题/卖点，没有任何现成文案。技能据此补齐缺失要素（渠道、受众、目标、语气、篇幅），再生成可直接发布的成稿。
- **Mode B · 文案改写**：用户已有一段原文，希望改得更好。技能先诊断原文问题，再按目标（润色/缩写/扩写/换风格/换渠道/纠错/提转化/去AI味）重写，并保留原文与改文的对照。

模式由输入自动判定：有原文 → Mode B；只有关键词无原文 → Mode A；两者都有 → 默认 Mode B（以原文为基底），若用户强调"全新写一版"则按 Mode A 重起。

## When to Use This Skill

触发条件（满足任一即启用）：
- 用户要求"写/生成/创作"某类文案，并给出主题或关键词
- 用户给出关键词并要求产出适配特定渠道的文案（"写条小红书""来个口播脚本""写个公众号标题"）
- 用户要求"改写/润色/优化/改一下/换种风格/缩短/扩写"一段已有文案
- 用户要求把同一内容改写成不同渠道版本（"把这篇公众号改成抖音口播"）
- 用户提到：写文案、写卖点、写slogan、写海报文案、写种草文、写朋友圈、写邮件、写广告语
- 英文触发：write copy, rewrite, polish, hook, caption, slogan, script

不适用：纯代码/技术文档撰写（用对应技术 skill）、长篇小说/学术专著创作、需要法律效力的合同文书。

## Mode 判定与输入解析

收到请求后，先按以下顺序判定：

1. **提取原文**：用户消息中是否包含一段可辨认的"待改文案"（成段文字、带引号内容、或附带的文本文件）。有 → 进入 Mode B。
2. **提取关键词/主题**：是否给出产品名、卖点、场景词、活动名等创作素材。有 → 进入 Mode A。
3. **两者都有**：默认 Mode B；若用户明确要求"不要参考原文、重写一版"，转 Mode A。
4. **都没有**：向用户追问最核心的一项——"你这次想写什么（主题/产品/活动）？发在哪个渠道？" 不要凭空编造产品事实。

判定后用对应的工作流执行。

## Mode A · 关键词创作工作流

目标：从零散关键词，产出渠道适配、可直接发布的成稿文案。

### A1. 补齐创作要素（缺失即合理追问，已给则沿用）

按优先级确认以下要素，缺失的不超过 2 项时可用合理默认，缺失过多则追问：

| 要素 | 默认 | 说明 |
|------|------|------|
| 渠道/类型 | 小红书种草文 | 决定结构与格式，见 `references/copy_types.md` |
| 主题/产品/活动 | 必填 | 不可编造，无则追问 |
| 核心卖点/关键词 | 必填 | 用户给的关键词，须全部覆盖 |
| 目标受众 | 该渠道典型用户 | 影响语气与切入点 |
| 传播目标 | 种草/涨粉/转化 | 决定 CTA 强弱 |
| 篇幅/条数 | 1 条，适该渠道 | 口播按秒数，图文按字数 |
| 语气调性 | 亲切自然 | 见 `references/style_guide.md` |
| 禁忌/必含 | 无 | 违禁词、须出现的品牌词等 |

### A2. 选模板

读取 `references/copy_types.md`，按渠道取对应结构模板（标题公式、正文骨架、格式要点）。无匹配渠道时，套用"通用短文案"骨架（钩子→价值→证明→CTA）。

### A3. 生成

- 把用户关键词**全部**织入正文，避免遗漏核心卖点。
- 严格遵循该渠道的格式规范：小红书加 emoji 与话题标签、口播按"钩子-痛点-方案-证据-行动"分镜、电商按 FAB 五要素、公众号标题用悬念/数字/冲突。
- 语气从 `references/style_guide.md` 取；禁止堆砌形容词与空话，每句要有信息量。
- 长度贴合渠道：小红书正文 300–600 字、口播 30s/60s/90s 三档、slogan ≤ 12 字、朋友圈 ≤ 80 字。

### A4. 质量门禁

生成后逐条过 `references/quality_checklist.md`。任一不通过则就地修订，不交付残次稿。

### A5. 交付

- 单条/短稿：直接输出到对话，前置一句话说明"渠道 + 篇幅 + 语气"。
- 多条（≥3）或多版本对比：写入 Markdown 文件，用 `present_files` 呈现，并在对话给结论。
- 始终附"可微调"提示，邀请用户给方向（"要更口语还是更专业？"）。

## Mode B · 文案改写工作流

目标：在保留用户核心信息的前提下，让原文更好用。

### B1. 诊断原文

读 `references/quality_checklist.md` 与风格库，对原文做快速体检，标注问题类型：
- 啰嗦/信息密度低
- 开头无力、缺钩子
- 语气错位（太硬/太软/太书面）
- 渠道格式缺失（无话题标签、无分段、无 CTA）
- 事实/数据存疑
- 错别字、语病、标点
- 违禁/绝对化用语（"最""第一""国家级"等需谨慎）

### B2. 确认改写目标

默认"全面润色"。若用户指定目标，优先执行该目标：
润色 / 缩写 / 扩写 / 换风格 / 换渠道 / 纠错 / 提升转化 / 去AI味。
目标不清时，列出 2–3 个可选项让用户选（用 AskUserQuestion 或直接在对话给选项）。

### B3. 重写

- 保留原文所有**事实信息**（数字、品牌、承诺），只改表达，不编造新增事实。
- 按目标调用对应策略（见下方"改写策略速查"）。
- 跨渠道改写（如公众号→口播）：重构为分镜/逐字稿，而非简单删减。
- 去AI味：砍掉"首先/其次/综上所述""值得一提的是"等套话，多用短句、口语、具体细节。

### B4. 对照交付

输出采用三段式：
1. **改后稿**（直接可用）
2. **主要改动点**（3–5 条，说明为什么改）
3. **原文对照**（长文写文件用 present_files，短则附后便于回看）

### 改写策略速查

| 目标 | 做法 |
|------|------|
| 润色 | 理顺逻辑、换掉空话、补钩子与 CTA |
| 缩写 | 删冗余、并句、保留核心卖点与 CTA，保信息不丢 |
| 扩写 | 加场景/痛点/证据/用户证言，不水字数 |
| 换风格 | 套 `style_guide.md` 调性库重写字词与节奏 |
| 换渠道 | 按 `copy_types.md` 重构成该渠道结构 |
| 纠错 | 改错别字语病、核实存疑表述、标出需用户确认的事实 |
| 提转化 | 强化痛点共鸣、加紧迫感与明确 CTA、前置利益点 |
| 去AI味 | 去套话、短句化、加具体细节与口语连接 |

## 通用铁律

1. **不编造事实**：产品参数、价格、政策、用户数据、资质奖项，原文没有就不写；确需示例时标注"[示例，待你确认]"。
2. **渠道优先格式**：每条文案先想"发在哪"，再决定结构、长度、emoji、话题标签、CTA。
3. **钩子在前**：无论哪种文案，前 2 行/前 3 秒必须抓住注意力（冲突、悬念、利益、反差）。
4. **口语自然**：像真人说话，不堆术语、不写长难句；中文文案用中文标点与表达。
5. **CTA 明确**：要么引导互动（点赞收藏）、要么引导行动（点击/下单/关注），不模糊收尾。
6. **合规底线**：规避《广告法》绝对化用语与医疗/功效违规承诺；不确定时标注待确认。

## Example Usage

**用户**："帮写一条小红书，推我们的便携咖啡机，卖点：一键出浓缩、颜值高、出差党友好"
→ Mode A：渠道=小红书，关键词=便携咖啡机/一键浓缩/高颜值/出差。取 copy_types 小红书模板，生成 300–600 字种草文 + 话题标签，过质量清单后输出。

**用户**："这段话帮我润色下：'我们公司是一个致力于为用户提供优秀产品和服务的企业……'"
→ Mode B：诊断"空话多、无钩子、无信息"，目标=润色+去ai味。重写突出具体产品与价值，给改动点 + 原文对照。

**用户**："把这篇公众号文章改成 60 秒抖音口播"
→ Mode B 跨渠道改写：读原文提炼核心，按口播分镜（钩子-痛点-方案-证据-行动）重构成逐字稿，标注秒数。
